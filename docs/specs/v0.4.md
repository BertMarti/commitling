# Spec: commitling v0.4.0 «Pro», generador en vivo con WebAssembly

Estado: propuesta del agente builder. Se fusiona con el primer PR del hito `v0.4.0`.

## Objetivo

Hoy la galería enseña variantes fijas y la criatura de BertMarti. La versión Pro deja que **cualquier persona escriba su usuario de GitHub en la web y vea al instante su commitling**, dibujada en su navegador por el **mismo código Go** que usa la CLI (compilado a WebAssembly). Sin servidor, sin token y sin datos que salgan del navegador salvo la petición pública a la API de GitHub.

Personas usuarias: quien quiere ver su criatura (y elegir especie y tema) antes de instalar la Action; quien quiere llevarse el SVG o el workflow ya relleno con su usuario.

Qué es «éxito»: escribir `BertMarti`, pulsar «Dibujar» y ver su criatura con el SVG idéntico (byte a byte) al que daría `commitling render --user BertMarti` con los mismos eventos y la misma fecha; poder descargar ese SVG y copiar un workflow que ya lleva su usuario.

## Supuestos (si alguno falla, se anota en MEMORY.md)

1. Los eventos se piden desde el navegador a `https://api.github.com/users/<u>/events/public?per_page=100&page=N` (N = 1..3, igual que el cliente de la CLI), sin token. La API admite CORS para esa ruta y expone `X-RateLimit-*` y `Retry-After`. Se verifica en el navegador.
2. No se envían cabeceras personalizadas (solo `Accept`, que es segura): así no hay petición previa de CORS.
3. El límite sin token es de 60 peticiones por hora y por IP. Cada generación gasta de 1 a 3 peticiones.
4. `wasm_exec.js` se toma de la instalación de Go del propio despliegue (`$(go env GOROOT)/lib/wasm/wasm_exec.js`): debe ser de la misma versión que el compilador.
5. Navegadores modernos con WebAssembly y `fetch`. Sin WebAssembly o sin JavaScript, la sección lo dice y el resto de la web sigue igual.
6. El código Go sigue usando solo biblioteca estándar.

## Alcance (mínimo que da el efecto «pro»)

1. **Función compartida** `internal/generate`: eventos JSON + opciones (usuario, especie, tema, fecha) -> SVG y descripción. La CLI `render` la usa para dibujar y el wasm también.
2. **Paquete wasm** `cmd/wasm` (`GOOS=js GOARCH=wasm`, `syscall/js`): una capa fina que expone tres funciones a JavaScript (dibujar, workflow, explicar un error de la API). Nada de lógica propia.
3. **Sección «Pruébalo con tu usuario»** en la galería: usuario, selector de especie y de tema, botón «Dibujar», vista previa, botón para descargar el SVG y el workflow relleno con botón de copiar. Sin dependencias JS; carga diferida del wasm.
4. **Despliegue y CI**: el workflow de Pages compila `commitling.wasm` (`-ldflags="-s -w"`) y copia `wasm_exec.js`; el CI comprueba que el wasm compila. Ninguno de los dos archivos se sube al repositorio.
5. **Documentación**: README, `docs/USO.md`, `CHANGELOG.md` (Sin publicar) y `MEMORY.md` (con el peso del wasm).

## Fuera de alcance

- Token de GitHub en el navegador, inicio de sesión o cualquier almacenamiento de datos de la persona.
- Una API o un servidor propio, proxys de CORS, caché en servidor.
- Reintentos con espera en el navegador (el cliente de la CLI ya los tiene; en la web se explica el fallo y se deja reintentar a mano).
- Editar estadísticas a mano, comparar usuarios, galería de usuarios, animaciones nuevas o especies nuevas.
- Descargar PNG (solo SVG).
- Cambiar las reglas de XP, fases, ánimos o el aspecto del SVG de la Action.
- Service worker o modo sin conexión.

## Tecnología

Go 1.27 (solo stdlib), `syscall/js`, `wasm_exec.js` de Go, HTML/CSS/JavaScript sin dependencias (un único `generator.js` embebido en la galería). GitHub Pages para el despliegue.

## Comandos

```
# Preparación (Windows/Git Bash)
export PATH="$PATH:/c/Program Files/Go/bin"; export GOTMPDIR="$PWD/out/gotmp"; mkdir -p out/gotmp

# Calidad (obligatorio antes de cada commit)
gofmt -l .                      # debe salir vacío
go vet ./...
go test ./...

# wasm
GOOS=js GOARCH=wasm go vet ./cmd/wasm
GOOS=js GOARCH=wasm go build -ldflags="-s -w" -o site/commitling.wasm ./cmd/wasm
cp "$(go env GOROOT)/lib/wasm/wasm_exec.js" site/

# Web local (primero `go run ./cmd/commitling gallery --out site`)
python -m http.server 8080 --directory site     # http://localhost:8080/ ; cerrar al terminar
```

## Estructura

```
internal/generate/   Render(eventsJSON, Options) -> SVG; Workflow(Options); FetchError(...)  [testeado con go test]
cmd/wasm/            main.go (//go:build js && wasm): registra commitling.render/workflow/explain; sin lógica
internal/gallery/    plantilla index.html.tmpl (sección del generador) + generator.js embebido
cmd/commitling/      render usa generate.Render (mismo código que el wasm)
.github/workflows/   ci.yml (compila el wasm) y deploy.yml (compila y publica wasm + wasm_exec.js)
docs/specs/v0.4.md   esta spec
```

Si medir el wasm demuestra que `net/http` (enlazado porque `internal/github` mezcla cliente y parser) lo engorda de forma notable, se separa el parser de eventos en un paquete sin red y `internal/github` conserva alias, sin cambiar su API pública ni sus tests.

## Estilo de código

Mismo que el repositorio: `gofmt`, nombres en inglés, comentarios que explican el porqué, errores en español para quien usa la herramienta, tests de tabla.

La interfaz web sigue «papel y píxel» (fondo `#f3efe6`, tinta `#2b2724`, línea `#ddd5c6`, monoespaciada, píxeles nítidos, sin degradados ni sombras), con tema oscuro por `prefers-color-scheme`, contraste AA, `prefers-reduced-motion` y español.

## Estrategia de pruebas

- **Go (`go test ./...`)**: toda la lógica vive en `internal/*` y se prueba ahí con TDD. `generate.Render`: especies y temas válidos e inválidos, JSON roto, usuario no válido, eventos vacíos, fecha dada y fecha por defecto. **Determinismo**: para los mismos eventos y la misma fecha, `generate.Render` y `commitling render --fixture ... --now ... --user ...` dan los mismos bytes (también con los eventos en otro orden o duplicados). `generate.Workflow`: lleva `user`, y `species` y `theme` solo si no son los valores por defecto; sin personalizar coincide con `gallery.WorkflowSnippet` más la línea `user`. `generate.FetchError`: 404, límite de peticiones (con y sin hora de reinicio), 5xx, red.
- **Compilación wasm**: `GOOS=js GOARCH=wasm go vet` y `go build` en el CI.
- **Web (manual, en el navegador del panel)**: servir `site/` con `python -m http.server`; escribir `BertMarti` y comprobar que sale la criatura; usuario inexistente; usuario no válido; sin red; solo teclado; tema claro y oscuro; ancho de móvil. Tests de Go sobre la plantilla (estado inicial oculto, `aria-live`, sin recursos de terceros, contraste de los colores nuevos).
- **Cobertura**: sin umbral numérico, pero cada rama de `internal/generate` tiene test.

## Límites

- **Siempre**: leer `MEMORY.md`; rama y PR por issue contra `main`; `gofmt`, `go vet`, `go test ./...` en verde antes de cada commit; commits convencionales en español con el pie del agente; no insertar nada externo en la página con `innerHTML` (el SVG lo genera Go y el usuario se valida con `github.ValidLogin`); avisos de estado y error en una región `aria-live`; actualizar `MEMORY.md`, README, `docs/USO.md` y CHANGELOG.
- **Preguntar antes**: añadir dependencias (Go o JS), cambiar la API pública de `internal/github` o las reglas de XP, subir el wasm o `wasm_exec.js` al repositorio, cambiar permisos de los workflows.
- **Nunca**: fusionar PR, crear etiquetas o releases, hacer commit a `main`, guardar o enviar tokens, pedir un token en la web, cargar scripts o fuentes de terceros, mandar el usuario a otro sitio que no sea `api.github.com`, descargar el wasm antes de que la persona interactúe con el generador.

## Criterios de aceptación

1. `internal/generate.Render` existe, está probado y es lo que usa `commitling render`; el test de determinismo CLI-contra-función pasa.
2. `GOOS=js GOARCH=wasm go build -ldflags="-s -w" ./cmd/wasm` compila en el CI; `commitling.wasm` y `wasm_exec.js` salen del workflow de despliegue y no están en el repositorio.
3. La web desplegada tiene el generador: con un usuario real (`BertMarti`) aparece su criatura en el navegador en pocos segundos; el selector de especie y de tema la redibuja.
4. El wasm solo se descarga cuando la persona interactúa con el generador (enfocar el campo, pulsar «Dibujar» o cambiar un selector); al abrir la página no se pide.
5. Estados accesibles: cargando, éxito y error se anuncian en una región `aria-live`; todo se puede usar con teclado; contraste AA en claro y oscuro; el formulario funciona con Intro.
6. Errores claros en español: usuario no válido (sin llamar a la API), usuario inexistente (404), límite de 60 peticiones por hora (con cuándo se reinicia, si la API lo dice), fallo de red y navegador sin WebAssembly.
7. Botón «Descargar SVG» (`commitling-<usuario>.svg`, el mismo SVG de la vista previa) y fragmento de workflow ya relleno con el usuario (y la especie y el tema elegidos) con botón de copiar.
8. Peso del wasm medido y anotado en `MEMORY.md`. Referencia medida antes de empezar (`-s -w`, Go 1.27): 4,5 MB sin comprimir con render y JSON; 7,1 MB con el paquete `internal/github` tal cual; 12,4 MB con el cliente HTTP en el wasm. Con gzip: 1,2, 2,0 y 3,3 MB. Con el parser de eventos separado de `net/http` (paquete `internal/events`, hecho en la primera issue) y `internal/generate`: 5,1 MB y 1,4 MB con gzip.
9. README, `docs/USO.md`, `CHANGELOG.md` (Sin publicar) y `MEMORY.md` actualizados.

## Riesgos

| Riesgo | Mitigación |
|---|---|
| El wasm de Go pesa varios MB | `-ldflags="-s -w"`, GitHub Pages sirve gzip, carga diferida, sin `net/http` si compensa (ver Estructura); medir y anotar |
| CORS o cabeceras no expuestas en la API | Solo `Accept`; si `X-RateLimit-Reset` no se puede leer, el mensaje no da hora |
| 60 peticiones/hora por IP se agotan (oficinas, redes compartidas) | Mensaje claro con hora de reinicio, máximo 3 peticiones por intento, no se repite solo; la Action con token sigue siendo el camino fiable |
| `wasm_exec.js` y el compilador de distinta versión | Se copia del mismo `GOROOT` en el mismo job |
| Diferencia entre navegador y CLI (zona horaria, fecha) | Todo se calcula en UTC; la fecha de referencia se pasa a la función compartida; test de determinismo |
| Inyección con un usuario o un SVG malicioso | `ValidLogin` antes de pedir nada; el SVG sale de Go (con `render.Escape`) y se muestra como imagen (`<img>` con URL `blob:`), nunca con `innerHTML` |
| Sin JavaScript o sin WebAssembly | La sección queda oculta o con un aviso; la galería sigue funcionando |
| Windows bloquea binarios de Go a veces | Reintentar el comando |
